# プライバシー { #privacy }

すべてはお使いのマシンの中で完結します。

- サーバーは localhost（`127.0.0.1`）でのみ待ち受けます。ほかのホスト名宛てのリクエストは
  拒否します。
- Claude Code のログは読み取り専用で読み込みます。
- 書き込むファイルは 2 つです。全文検索インデックスはログ内テキストのキャッシュで、ユーザーの
  キャッシュディレクトリに置かれます（[全文検索](features.md#full-text-search) を参照）。その隣に SQLite の
  `-wal` と `-shm` ファイルがあります。削除しても問題なく、次回起動時に再構築されます。メモファイルには、
  セッションに付けたメモ、タグ、評価が保存されます（[メモとタグ](getting-started.md#notes-and-tags) を参照）。
  このファイルはメモ、タグ、評価を変更したときにだけ書き込まれます。ファイルを読み込めない場合は決して上書きせず、
  修正されるまでメモ機能は無効になります。`--search-index` と `--notes` でこれらのファイルの場所を変更できます。
- ほかの Web サイトのページからメモを変更することはできません。サーバーは自身のページから送られた
  JSON による変更しか受け付けません。
- 唯一のネットワークリクエストは、PyPI に cc-calendar の最新バージョンを問い合わせるものです
  （`https://pypi.org/pypi/cc-calendar/json`）。起動時と 1 日 1 回行い、アップデートの公開を知らせます。
  リクエストの User-Agent には実行中のバージョンが含まれますが、セッションに関する情報は一切含まれません。
  `--no-update-check` または `CC_CALENDAR_NO_UPDATE_CHECK=1` で無効にでき、その場合
  cc-calendar はネットワークリクエストを一切行いません。
- ページは外部のスクリプト、フォント、アナリティクスを読み込みません。
- ログを表示してもほかのホストに接続することはありません。トランスクリプト内でリンクされた画像（`![](https://…)` や
  `<img>` タグ）は読み込まれず、自分で開けるリンクとして表示されます。ページの
  Content-Security-Policy により、ブラウザーがほかのサイトから何かを読み込むことはありません。
- ログに現れないコミットハッシュもあります。それらはセッションの作業ディレクトリで `git log` を使って
  調べます。詳細ペインでも同じ場所で `git status --porcelain` を実行し、
  作業ツリーがクリーンかどうかを表示します。
- Markdown レポートは、`#N` 形式の参照を各セッションのリポジトリの `origin` リモートにリンクします。
  リモートは `git remote get-url origin` で読み取るだけで、リモートに接続することはありません。

このサイトのスクリーンショットとリポジトリのテストデータは架空のものです。
`scripts/demo_data.py` で生成しています。

セキュリティ上の問題を報告する場合は、
[セキュリティポリシー](https://github.com/atinfinity/cc-calendar/blob/main/SECURITY.md)を参照してください。
